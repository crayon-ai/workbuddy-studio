# 选题池表格视图（卡片/表格双视图切换）设计

日期：2026-08-24
状态：已确认（方案 A：紧凑多列表，草图 review 通过）

## 背景与目标

选题池当前只有卡片视图（2 列 grid，每卡含阶段流程条、立意、素材入口、推进按钮）。当选题数量增多时，卡片占空间大、无法一屏扫完全局字段。

新增**表格视图**：每行一个选题，紧凑多列，信息密度高。两种视图可切换，展示的数据与筛选逻辑完全一致，只是呈现形式不同。

## 方案选型

草图阶段对比两案，用户选定 **方案 A：紧凑多列表**：

- A（选定）：10 列紧凑行表，标题单行截断，阶段用「标签 + 迷你进度点」双呈现，分类/平台/截止/更新各占一列
- B（否决）：9 列宽行 + 标题下立意副行，行高松但一屏行数少

## UI 设计

### 视图切换

- 位置：`#topicFilters` 筛选 pill 行的右侧（`margin-left:auto`），胶囊分段控件（同现有 chip 风格）
- 两个按钮：「▦ 卡片」「≡ 表格」，选中态珊瑚橙渐变白字，未选中灰
- 切换只换渲染形式，当前筛选条件（f pill 的 active）保留不动
- 视图偏好存 localStorage（key：`wb_topic_view`，值 `card` / `table`），下次进入保持

### 表格视图（10 列）

| 列 | 内容 | 来源字段 |
|---|---|---|
| 状态 | 阶段标签 pill（复用 `c-tag` 的 `t-draft/t-final/t-card/t-publish` 配色） | `FLOW[type].txt[stage]` |
| 选题标题 | 加粗、单行截断（max-width + ellipsis） | `t.t` |
| 类型 | `📝 图文 / 📺 视频 / ✍️ 文本` | `t.type` |
| 进度 | 迷你进度点（每阶段一个 9px 圆点：已完成=抹茶绿、当前=珊瑚橙+光晕、未来=底灰） | `stage` vs `FLOW[type].steps.length` |
| 素材 | `📂 N` 链接按钮，点击打开选题素材弹层（同卡片） | `t.mats.length` |
| 分类 | `观点/方法/测评` | `t.cat` |
| 平台 | `小红书/抖音/…`（多平台 `+` 连接，可换行） | `t.plat` |
| 截止 | `MM.DD` | `t.due` |
| 更新 | `刚刚/2 小时前/…` | `t.update` |
| 操作 | 「继续推进 →」（未完成）/「查看数据」（已完成，toast 提示去复盘） | 同卡片逻辑 |

### 交互与视觉规则（与卡片视图对齐）

- 排序：未完成在前、已完成在后（同 `renderTopic` 现有 sort）
- 已完成选题：整行降透明度（`.dim`，同卡片 `topic-done`）
- 筛选：复用 `#topicFilters` 现有事件，切换 f 后按当前视图重渲染
- 行 hover：奶油底色高亮
- 空态：无选题时表格区域显示与卡片一致的空状态文案
- 表格容器允许横向滚动（窄屏 10 列放不下时），行内重要列（状态/标题/操作）不压缩

## 实现要点

全部改动在 `自媒体工作台.html` 单文件内，纯前端，无后端/数据结构变化：

1. **HTML**：`#topicGrid` 后新增 `<div id="topicTableWrap">`（内含 `<table id="topicTable">`，初始按 localStorage 偏好显示其一）
2. **JS**：
   - `renderTopic(f)` 改为按当前视图分发到 `renderTopicGrid(f)`（原逻辑抽出）或 `renderTopicTable(f)`
   - 两者共用同一份 list 构造（filter + sort + doneOf），避免两份口径漂移
   - 新增 `setTopicView(v)`：切换按钮态 + 显示/隐藏两个容器 + 存 localStorage + 重渲染
   - 行内按钮直接复用现有 `openTopicMat(idx)`、`advanceTopic(idx)`，无新逻辑
3. **CSS**：新增 `.topic-table` 相关样式（表头奶油底、行 hover、迷你进度点、标题截断），放选题池样式区块附近
4. **标题编辑入口**：本期表格内点标题暂不做编辑跳转（卡片视图也没有编辑入口，保持一致，避免范围蔓延）
