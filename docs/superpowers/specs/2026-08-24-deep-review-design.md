# 深度复盘（对标笔记对比分析）设计

日期：2026-08-24
状态：已确认（方案 B：双阶段编排）

## 背景与目标

现有复盘模块是纯本地手动流程：粘贴自己的笔记链接 → 后端秒抓元数据（赞藏评/发布时间/标签）→ 手动打分 + 手写分析。洞察只有两条固定规则（赞藏评合计、收藏/点赞比）。

新功能：复盘时可以提供几篇**同赛道、发布时间相近**的对标笔记，AI 对比自己笔记与对标笔记的**内容差异**，结合数据差距做归因分析（「我 200 赞、同赛道同期 2 万赞，差在哪」），产出可执行的调整建议。

### 已确认的关键决策

| 决策点 | 结论 |
|---|---|
| 对标来源 | 手动收集（粘贴链接），不做自动搜索推荐 |
| 触发时机 | 复盘弹窗内手动触发 |
| 产物形态 | 独立报告（落盘 + task），弹窗内展示摘要 |
| 分析深度 | 含正文 + 封面图（vision），**不分析评论区**（拿不到） |
| 技术路线 | 方案 B：后端双阶段编排（秒抓元数据 → 逐篇下载 → 纯分析 skill） |

### 不做（YAGNI）

- 不做对标链接跨笔记复用库
- 不做自动搜索/推荐对标
- 不改现有手动复盘流程（不打分也能深度复盘）
- 不分析评论内容（只看评论数量）

## 用户流程

复盘弹窗内新增「🎯 深度复盘」区域（`rvInsight` 下方）：

1. **收集对标**：输入框粘贴对标笔记链接（1-5 条），点「拉取对标数据」
   - 每条走现有 `POST /api/note` 秒拿元数据，卡片式展示：标题/赞藏评/发布时间 + 与自己笔记的时间差（如「晚 3 天发布」）
   - 可删除不合适的；确认后点「开始深度分析」
2. **异步任务**：`POST /api/deep-review` 创建 task，前端轮询（同爆款拆解模式），进度提示：「抓取正文封面 → 对比分析中 → 完成」
3. **报告呈现**：完成后弹窗内显示报告核心结论 + 数据对比摘要，完整报告在 `data/deep-reviews/<taskId>/`，「打开文件夹」按钮直达
4. **关联持久化**：笔记的 localStorage 记录存 `deepReviewTaskId`，再次打开弹窗直接显示已生成报告；重新生成创建新 task，旧文件保留

## 后端架构

新增 `server/src/routes/deep-review.ts`（对照 `personalized.ts` 模式）+ 新 skill `deep-review`。

```
POST /api/deep-review            { noteUrl, benchmarkUrls[] } → { taskId }
GET  /api/task/:id               复用现有轮询
GET  /api/deep-review/:id/folder 打开产物文件夹（同 teardown）
POST /api/deep-review/:id/reparse 从磁盘恢复报告（同 teardown）
```

### 编排三步（runDeepReview）

**① 元数据阶段**（纯 Node，秒级，零 token）
- `Promise.allSettled` 对自己笔记 + 全部对标并行跑 `fetchNoteMeta`（note.ts 导出复用）
- 失败的对标剔除，记录进报告「数据说明」
- 计算确定性数据信号，落盘 `workDir/meta.json`：
  - 收藏/点赞比、评论/赞比
  - 发布时间差（相对自己笔记）
  - 标签重合度（<2 个共同标签时报告提醒「可能非严格同赛道」）
  - 作者粉丝数（从笔记页 SSR 尽力提取，拿不到跳过）

**② 下载阶段**（每篇一次独立 agent 调用，失败隔离）
- 对元数据成功的每篇（自己的 + 对标的）逐篇调 `runSkill("baokuan-chaijie", 只下载 prompt)`，产物落 `workDir/notes/<角色>-<标题>/`
- prompt 明确：只执行能力一（下载正文+图片），**跳过评论区**，不拆解
- 单篇失败不阻塞：标记降级，该篇仅参与元数据对比
- 进度逐篇上报「2/4 篇下载完成」

**③ 分析阶段**（一次 agent 调用）
- 新 skill `.claude/skills/deep-review/`：读 meta.json + 各篇下载目录，产出 `workDir/AI深度复盘-<自己笔记标题>.md`
- 沿用 teardown 的磁盘恢复 + 防编造检测（产物含「模拟数据/示例内容」判 failed）

### 分析方法论（skill 的核心逻辑）

**分工**：
- 后端算（确定性、零 token）：比值信号、时间差、标签重合度、粉丝数
- LLM 判（模板钉死维度）：钩子类型、封面、正文结构、归因排序、建议

**单篇内容诊断四维**（每篇同一模板，对称分析）：
1. 标题钩子：类型（数字清单/反常识/身份代入/损失规避/利益承诺）+ 强度
2. 封面：文字密度、视觉冲突、信息传达效率
3. 正文结构：开头钩子、信息密度、可操作性、排版节奏
4. 内容完整度：信息缺口、「带走资产」价值感

**归因核心**：数据差距 → 内容归因。找表现最好/最差对标，逐维度对比，按影响度排序（标题钩子 > 封面 > 正文结构），每条归因指出「对标哪篇的什么具体做法」vs「我这篇对应位置的差距」。

## 报告结构（skill 输出契约）

`AI深度复盘-<标题>.md` 五部分：

1. **数据对比总览**：表格——自己 vs 各对标的赞/藏/评/发布时间/时间差/标签重合度/粉丝数
2. **对标逐篇诊断**：每篇按四维模板，好/不好都要给具体内容证据
3. **差距归因**：按影响度排序的归因链，绑定双方具体内容
4. **可执行建议**：3-5 条可直接照做，每条注明依据（哪篇对标的什么证据）
5. **可复用经验候选**：1-3 条短句，前端可一键带入复盘的经验输入框

## 错误处理

- 对标元数据失败 → 剔除 + 报告注明，其余继续
- 全部对标失败或自己笔记元数据失败 → task failed，提示检查链接
- 下载单篇失败 → 降级元数据对比，报告标注「该篇正文未获取」
- 分析 skill 失败/零产物/编造 → task failed 可重试；磁盘有产物自动恢复
- 前端轮询 failed → 明确提示 + 重试按钮
