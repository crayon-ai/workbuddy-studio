# 数据导出与导入设计

日期：2026-08-26
状态：已确认（方案 A：纯前端 JSON 文件）

## 背景与目标

工作台业务数据全在前端 localStorage（后端无状态）。浏览器清缓存 = 数据全丢。提供导出/导入能力：导出成文件保存，清缓存后导入恢复。

## 已确认决策

- **方案**：纯前端 JSON 文件（零后端改动）
- **导入策略**：整体覆盖（恢复到备份时点），不合并
- **入口**：侧边栏「设置」组新增「数据导出与导入」项，点击弹窗

## 数据面（12 个 key，导出 10 个）

| key | 内容 | 导出 |
|---|---|---|
| `workbuddy_v3` | 选题池+复盘笔记+日历+今日完成 | ✓ |
| `wb_insp` / `wb_insp_topic` / `wb_mats` / `wb_hits` | 灵感/关键词/素材/拆解记录 | ✓ |
| `wb_avatar` / `wb_user` / `wb_first_use` / `wb_profile_url` | 头像/昵称/首用日期/主页链接 | ✓ |
| `wb_theme` | 主题选择 | ✓ |
| `wb_running_task` / `wb_running_insp_task` | 进行中任务（临时态） | ✗ |

## 交互设计

侧边栏「设置」小标题下新增第三项「**数据导出与导入**」（图标：软盘/交换箭头，样式同「外观主题」「AI 配置」两项）。点击弹出弹窗：

- 标题「数据导出与导入」，副标题说明用途（备份/恢复，清缓存不丢数据）
- **导出区块**：说明文字（导出全部工作台数据为 JSON 文件）+ 按钮「📥 导出数据」。点击触发浏览器下载（系统保存对话框，用户选保存位置），文件名 `workbuddy-backup-YYYY-MM-DD.json`
- **导入区块**：说明文字（选择之前导出的备份文件，导入将覆盖当前全部数据）+ 按钮「📤 导入数据」。点击唤起系统文件选择器（accept=.json），选中后：校验 → `confirm`「导入将覆盖当前全部数据，确定继续？」→ 写回 → 刷新页面
- 底部小字：建议定期导出备份

## 文件格式

```json
{
  "app": "workbuddy",
  "version": 1,
  "exportedAt": "2026-08-26T12:00:00.000Z",
  "data": {
    "workbuddy_v3": "<原始 JSON 字符串>",
    "wb_insp": "<原始 JSON 字符串>",
    ...
  }
}
```

- `data` 的 value 存**原始字符串**（不二次解析），导入时直接原样写回 localStorage——避免对内部结构做任何转换，天然向前兼容
- 备份里缺的 key：导入时从 localStorage 删除该 key（保证「恢复到备份时点」语义）

## 导入校验（容错）

1. JSON parse 失败 → toast「文件不是有效的备份文件」，不动任何数据
2. `app !== "workbuddy"` → toast 同上
3. `data` 非对象 → toast 同上
4. `version > 1`（未来版本文件）→ toast「备份文件版本更高，请升级工作台」
5. 通过 → confirm 二次确认 → 覆盖写入 → `location.reload()`

## 不做（YAGNI）

- 不做部分导入/选择性导入
- 不做自动定时备份（后端方案已否）
- 不做合并导入

## 测试

前端无单测（项目惯例）。手动验收：
- 导出：文件下载成功、内容含全部 10 个 key、JSON 合法
- 导入：改几条数据 → 导入旧备份 → 刷新后回到备份时点状态（含主题、头像）
- 容错：选一个普通 JSON/文本文件 → toast 报错且数据未动
- 双份同步（根目录 + release/WorkBuddy）
