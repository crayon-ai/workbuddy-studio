# 爆款素材拆解 Skill

识别赛道、匹配公式，把拆解写入 `<workDir>/structure.md`；原文（正文/图片/逐字稿）归档到原文库目录。

## 调用架构（谁干什么）

| 环节 | 执行者 |
| --- | --- |
| 抓正文 / 下图片 / 下视频 / ffmpeg / whisper 转写 | **调用方后端直连**（主路径，agent 不参与，分钟级 → 秒级） |
| 图片内文字识别、赛道识别、公式匹配、理由 | agent（本 skill） |
| 原文脚本（逐字稿/正文全文）拼进 structure.md 的「## 脚本」节 | 调用方后端（机械拼接） |
| 评论区 | 不抓取（拆解只需要素材本身的内容） |

后端直连失败（平台反爬/非常规页面）时，回退【模式 B】由 agent 全流程抓取。

## 核心理念

1. **识别与匹配，不是自由归纳**：结构不由本 skill 发明——调用 prompt 附带公式清单，每条公式自带固定结构模板。本 skill 只做三件事：给素材归一个赛道、从清单里选出最命中的一条公式、说明理由。**必须且只能选清单里的一条**，不允许自创结构。
2. **脚本要原样，不要加工**：工作台要的是「这条爆款的原话」——但抄写由调用方从原文库逐字稿/正文直接拼接完成，agent 不抄、不总结、不缩写、不润色。
3. **钩子的精髓常不在正文文字里**：小红书图文的钩子多半在封面图上，视频的钩子在口播前 3 秒。所以**图片文字和视频逐字稿是拆解的必备输入**，不是可选项——只看正文文字是拆不准的。

## 模式 A：识别与匹配（原文已备好，禁止联网）

prompt 给出 `<原文目录>`（复用已归档原文，或后端直连刚抓好的）。**不要发任何网络请求**：

1. 用 Read 读取 `正文.md`、`逐字稿.md`（存在哪个读哪个，都存在都读）。
2. 若存在 `图片/` 目录且没有 `图片文字.md`：逐张 Read 图片（webp/avif 先用 ffmpeg 或 sips 转成 jpg），把图内文字（封面钩子、图卡标题、步骤文字）整理写入 `图片文字.md`——封面一句话钩子往往是整篇最关键的素材；单张失败跳过并注明，绝不允许编造。已有 `图片文字.md` 则直接 Read。
3. 若目录内容为空或只有占位元信息（无正文内容也无逐字稿）：如实说明并停止，不写 structure.md，也不要自行联网下载。

## 模式 B：agent 兜底全新抓取（后端直连失败时）

抓全量 + 归档到 `<原文库目录>`，纪律同上（不登录、不编造、不抓评论区）：

1. **抓正文**：Bash 执行 curl（带浏览器 UA；乱码/压缩数据加 `--compressed` 重试；-L 跟随跳转），从页面内嵌 JSON 提取（小红书看 `__INITIAL_STATE__` 的 noteDetailMap），存 `正文.md`（开头一行标题）。
2. **图片与图内文字**：正文/封面图片下载到 `图片/`（webp/avif 先用 ffmpeg 或 sips 转成 jpg 再分析），逐张识别整理 `图片文字.md`；单图失败跳过并注明。
3. **视频转逐字稿**：下载视频（探索页面 API，B站可走 html5 playurl），`ffmpeg -i 视频.mp4 -vn -ar 16000 -ac 1 音频.wav`，本机 127.0.0.1:2022 whisper server（OpenAI 兼容 `/v1/audio/transcriptions`，**必须带 language=zh**，音频大时先切分再逐段转写拼接），存 `逐字稿.md`；whisper 不可用则如实说明并跳过。
4. **不抓评论区**：评论一律不抓取、不翻页、不归档。

## 识别与匹配（两种模式相同）

通读全部素材（正文 + 图内文字 + 逐字稿），写 `<workDir>/structure.md`，**只包含三节**，格式严格照调用 prompt：

- **赛道**：一个词，从内容本身归纳（美食 / 职场 / AI工具 / 旅行 / 穿搭…均可，不设清单）。
- **公式**：对照 prompt 附的公式清单（`- f1｜名称` 一行一条），选出**最命中的一条**，输出它的 **id**（如 `f5`）。必须且只能选一条；都相像时选最接近的，并在理由里说明取舍。
- **匹配理由**：一句话，对照命中公式的结构特征说清「这篇素材怎么就符合它」，要具体（点出素材里的实际做法），不许空话。

**不要写「## 脚本」节**——脚本由调用方从原文库拼接。若最终没抓到有效原文，如实说明失败原因并停止，不写 structure.md。
