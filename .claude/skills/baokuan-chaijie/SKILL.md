# 爆款拆解 Skill

本 skill 包含**三个独立能力**，用户通常分开调用：

- **能力一：下载笔记原文** —— 用户给**链接** + **指定主题**，把原文素材（文字/图片/视频）下载到该主题文件夹下的「爆款原文」里。
- **能力二：拆解爆款笔记** —— 用户给**笔记标题**，对已存在的原文做多维拆解，产物放到同主题下的「AI拆解」里。
- **能力三：主题共性分析** —— 在**已收集并拆解好一批爆款之后**，用户给**一个主题**，把该主题下已有的爆款原文 + 拆解放在一起做组合（横向）分析，提炼共性与「没人深挖的空白点」，产物放到同主题下的「AI拆解」里。

## 目标目录与主题文件夹（三个能力的公共锚点）

**下载/输出的根目录完全由用户指定**（记为 `<目标目录>`）——用户说下到哪就放到哪，不再固定任何前缀。用户可以给绝对路径（如 `~/Desktop/爆款库`）或相对路径。在此根目录下，再按用户指定的**主题**分子文件夹归档：

```
<目标目录>/<主题>/
├── 爆款原文/          # 能力一的产物：每帖一个以标题命名的文件夹
│   └── <笔记标题>/    正文.md + 图片/ + 视频.mp4
└── AI拆解/            # 能力二/三的产物
    ├── AI爆款拆解-<笔记标题>.md   # 能力二：每篇笔记一个拆解文档
    └── 主题共性分析-<主题>.md      # 能力三：整个主题一份共性分析报告
```

- **目标目录必须来自用户**：若用户没说下载/输出到哪，**先主动询问要放到哪个目录**，不要自作主张写到某个固定目录。
- **主题为可选的二级归类**：用户若指定了主题就建 `<主题>/` 子目录；若用户只给目录、不分主题，可省略主题层，直接用 `<目标目录>/爆款原文/`、`<目标目录>/AI拆解/`。同样在不清楚时可询问。
- 同一篇笔记的原文与拆解**必须在同一根目录（及同一主题）内**，一一对应。
- 下文所有示例路径里出现的 `<目标目录>` 都指代用户指定的这个根目录。

用于把一篇帖子/视频，拆解成一份可复用的「爆款分析报告」，并按固定规范归档。

## 什么时候用

- **能力一触发**：用户给出**帖子/笔记链接**（常伴随一个主题），说「帮我下载/保存这篇笔记的原文」。
- **能力二触发**：用户给出**笔记标题**，说「帮我拆解这篇爆款笔记」。
- 用户给出一个视频文件（.mp4/.mov 等）要求拆解。
- **能力三触发**：用户要求**对之前已收集、拆解好的爆款做组合（主题级）分析**——即给出**一个主题**（或说「把这个主题下已经拆解好的爆款放一起组合分析/找共性/找可深挖的方向」），基于该主题下已有的原文与拆解，横向总结共性情绪、共性痛点、共性内容，以及多篇都隐含却没深挖的点。

三个能力可分可合：用户通常**先用能力一攒一批原文 → 再用能力二逐篇拆解 → 最后用能力三对这批已拆解好的爆款做组合分析**。

## 核心原则（务必遵守）

1. **图片里的文字必须提取**：帖子的关键内容常在图片里，markdown 纯文本不全面。遇到图片，**必须用 `analyze_image` 把图片转成文字**再分析，不能只看正文。
2. **视频先转逐字稿再拆解**：视频不能直接拆，必须先生成逐字稿文件，再对逐字稿走 9 维拆解。
3. **拆解要落到「可复用」**：不只描述现象，要提炼出标题公式、钩子公式、结构模板、情绪曲线，让用户能直接套用。
4. **产出必须归档**：拆解结果写入**同一根目录（同主题）下**的 `AI拆解` 目录（与「爆款原文」同级），**每个笔记一个拆解文档**，文件名格式：`AI爆款拆解-<笔记标题>.md`。命名规范见下。
5. **末尾附原文**：拆解文档末尾必须有 `## 原文` 章节，贴入完整提取内容（图片文字 + 正文 / 逐字稿），方便对照。

## 零、根据链接下载并归档原文素材

当用户给出一个帖子/笔记**链接**时，先把原文素材完整抓取归档，再进入拆解。

### 目标产物

在用户指定目录的「爆款原文」下，**为每个帖子创建一个以帖子标题命名的独立文件夹**，把该帖的所有素材放进去：

```
<目标目录>/<主题>/爆款原文/<帖子标题>/
├── 正文.md          # 标题 + 作者 + 正文文字 + 话题标签 + 原链接 + 平台/发布时间/互动数据（若可得）
├── 图片/            # 小红书图文卡片：img_01.jpg, img_02.jpg ...（按顺序命名）
└── 视频.mp4         # 小红书视频帖：下载 mp4（图文帖则无此文件）
```

> 若「爆款原文」目录尚不存在则创建。标题中的非法字符（`/ : * ? " < > |` 等）替换为下划线。

### 抓取规则（按平台）

- **小红书图文帖**：下载正文文字 + 所有图文卡片图片（按轮播顺序编号）。
- **小红书视频帖**：下载正文文字 + 视频 `.mp4` 文件。
- **微信公众号 / 其他平台**：同理——**有文字下文字、有图片下图片、有视频下视频**，全部保存到该帖文件夹。

### 执行步骤

1. **识别平台与内容类型**（图文 / 视频）。
2. **优先尝试解析页面**：用 `parse_link` 抓取标题、正文、话题标签、媒体地址。若拿不到（登录墙/反爬/短链），要求用户提供：可直接访问的原始链接、或已导出的正文/图片/视频文件。
3. **下载媒体**：拿到图片/视频直链后，用 `code_execution`（Node/Bash + curl/wget）下载到该帖文件夹。**必要时带 Referer/User-Agent 头**（小红书图片/视频 CDN 常校验 referer）。命令模板见 `references/download-post.md`。
4. **写正文文件**：用 `write_file` 生成 `正文.md`，含标题、作者、原链接、平台、可得的互动数据，以及完整正文与话题标签。
5. **核对完整性**：确认图片数量与卡片数一致、视频可播放；缺失项明确告知用户。
6. 完成后向用户报告归档路径与文件清单，并询问是否继续走 9 维拆解。

> ⚠️ 合规：仅用于个人学习与内容研究，尊重原作者版权，不用于二次分发。

> 拆解阶段的「原文素材」即来自此文件夹：图片走 `analyze_image` 提取文字，视频走「视频拆解流程」。

## 一、帖子/文章拆解流程

1. **读取原文**：读取用户指定的帖子/文档文件。
2. **提取图片文字**：如含图片，逐张用 `analyze_image` 提取文字（封面、正文页、演示截图都要覆盖）。若图片仅为无关推荐位/装饰，可注明「非正文内容」跳过。
3. **按 9 维度拆解**（见下方「九维度模板」）。
4. **输出到文件**：在 `<目标目录>/<主题>/AI拆解/` 下创建 `AI爆款拆解-<笔记标题>.md`。
   - 顶部 frontmatter + 指向原文的 Obsidian wiki 链接 `[[原文件名]]`（若原文素材已归档，链向「爆款原文」里的正文）。
5. **附录原文**：文档末尾追加 `## 原文` 章节，贴入完整提取内容（图片文字 + 正文文字）。

## 二、视频拆解流程（两步）

### 第一步：生成逐字稿

在视频文件所在目录下输出逐字稿：

- 文件名：`<原视频文件名去扩展名>-逐字稿.md`（如 `阿西出海-github-逐字稿.md`）
- 顶部标注：来源 wiki 链接 `[[原视频文件名.mp4]]`、时长、转写方式
- 生成步骤：
  1. 用 `ffmpeg` 从视频提取音频为 16kHz 单声道 WAV。
  2. 调用本地 Whisper 服务（默认端口 2022）转写，`language=zh`。
  3. 按章节分段，保留时间戳标记（如 `[00:12]`），方便对照原视频。
  4. 转写完成后删除临时 WAV 文件。

参考命令见 `references/video-transcribe.md`。这些命令需在**用户真实环境**执行（ffmpeg / 本地 Whisper 都在用户机器上），使用 `user_exec` 运行。

### 第二步：对逐字稿走 9 维拆解

- 参照「九维度模板」拆解。
- 输出到 `<目标目录>/<主题>/AI拆解/`，文件名 `AI爆款拆解-<视频标题或原视频文件名去扩展名>.md`。
- 顶部包含逐字稿的 wiki 链接 `[[原视频文件名-逐字稿]]`。
- 末尾 `## 原文` 章节贴入完整逐字稿。

## 三、九维度拆解模板

每篇拆解必须覆盖以下 9 个维度（顺序固定）。

1. **标题为什么吸引人？** — 拆出标题类型（SEO型/纠错型/承诺型/反差型…）与可套用的**标题公式**。
2. **开头用了什么钩子？** — 命名钩子类型（踩坑故事/转变金句/量化干货/认知反差…），拆钩子机制。
3. **正文结构是什么？** — 画出结构骨架（用代码块列分段），指出精妙之处。
4. **击中了用户哪些痛点？** — 用表格列「痛点 → 文中如何戳/解决」。
5. **调动了什么情绪？** — 画出情绪曲线（如「先压后抬」），总结情绪配方。
6. **用了哪些心理机制？** — 列出损失厌恶/社会认同/锚定/身份升级/互惠等，并对应原文。
7. **哪些地方制造了收藏/转发欲？** — 列触发点，提炼「收藏钩子公式」。
8. **最值得复用的结构是什么？** — 给出 🏆 黄金模板 + 次级技巧。
9. **如果迁移到用户账号，可以变成哪些选题？** — 分类给出可裂变选题清单。

**收尾**：加一段「一句话总结」，点破这篇爆款的本质。

详细写法与话术库见 `references/nine-dimensions.md`。

## 四、能力三：主题级共性分析（多篇横向对比）

当用户给出**一个目录/主题**（或说「把这个目录下的爆款放一起分析 / 找共性 / 找可深挖的方向」）时，把该目录 `AI拆解/` 下**所有已完成的单篇拆解**（以及必要时 `爆款原文/` 里的正文）汇总，做一份横向共性分析报告。

### 执行步骤

1. **收集样本**：列出 `<目标目录>/<主题>/AI拆解/` 下所有 `AI爆款拆解-*.md`，逐篇读取。样本至少 2 篇才有横向意义。
2. **逐篇抽取要素**：从每篇拆解里抽出「核心情绪 / 击中痛点 / 核心内容点 / 钩子」，在心里建一张对照矩阵。
3. **按下方 4 个板块产出报告**（第 4 板块是重点，篇幅要最大）。
4. **输出到文件**：`<目标目录>/<主题>/AI拆解/主题共性分析-<主题>.md`，顶部列出参与分析的所有笔记（wiki 链接）。

### 报告必含的 4 个板块

1. **共性情绪点** — 哪些情绪在多篇里被反复引导/使用？用表格列「情绪 → 出现在哪几篇 → 怎么被调动」。指出该主题的**通用情绪配方**。
2. **共性用户痛点** — 哪些痛点是多篇都在尝试解决的？列「痛点 → 命中的篇目 → 各自的解法」。
3. **共性内容点** — 哪些内容/母题/方法在多篇里都被提到？（如「找现成的别自造」「建一张表」「数据门槛」等）指出这是该主题的**标配内容**。
4. **⭐ 多篇都隐含却没深挖的点（重点，篇幅最大）** — 找出「几乎每篇都暗示/擦边提到、却没有一篇真正展开讲透」的点。这是用户可以建立护城河的**专属深挖方向**。
   - 按「含金量 + 差异化」排序，每个空白点写清：**多篇是怎么隐含暗示它的（举证）→ 为什么没人深挖 → 用户可以怎么把它做成自己的选题（你的机会）**。
   - 优先锁定那些「被多篇正文明确提及、却没有一篇展开讲透」的点——这类空白证据最确凿。

**收尾**：一句话战略建议，点明该主题「大家都卷在哪、真正的空白在哪、用户该切哪个点」。

详细写法与提炼话术见 `references/theme-synthesis.md`。
